# Odium — ТЗ сайта студии и доски пожеланий

Oct 1, 2026 · @Danil

Сайт игровой студии Odium на Next.js: витрина студии и её игр плюс публичная доска пожеланий по каждой игре с голосованием и модерацией. Отдельного бэкенда нет — API живёт в самом Next.js.

## 1. Обзор

Сайт показывает, кто такие Odium и какие игры студия сделала, и собирает от игроков пожелания по каждой игре. Смотреть всё может любой посетитель; создавать пожелания и голосовать — только зарегистрированные пользователи.

**Цели**

- Познакомить игроков и партнёров со студией: кто мы, чем занимаемся, ссылки на соцсети и сторы.
- Показать каталог игр с подробной страницей по каждой.
- Получать от игроков идеи «что добавить» и «что убрать» и видеть, какие из них важнее всего по голосам.
- Показывать игрокам, что студия их слышит: статусы пожеланий («Запланировано», «Сделано» и т. д.).

**Аудитория**: игроки студии (в основном с телефонов) и случайные посетители из поиска и сторов.

**Язык интерфейса**: русский. Структура текстов должна позволять позже добавить английский.

## 2. Стек и архитектура

Одно приложение Next.js делает и страницы, и API. Публичные страницы рендерятся на сервере и читают базу напрямую из Server Components. Изменения (пожелания, голоса, модерация) идут через Route Handlers (`app/api/**/route.ts`). Вся логика живёт в сервисном слое `lib/server/*`, а Route Handlers и страницы только его вызывают — проверки прав и лимитов не дублируются.

| Часть | Решение | Зачем |
| --- | --- | --- |
| Фреймворк | Next.js (актуальная версия), App Router, TypeScript strict | Серверный рендер для SEO и API в одном проекте |
| API | Route Handlers в `app/api` | Обычные HTTP-эндпоинты, которые потом можно вызвать из игры или мобильного приложения |
| База | PostgreSQL | Транзакции и уникальные ограничения для голосов |
| ORM и миграции | Drizzle ORM + drizzle-kit | Типизированные запросы, близко к SQL |
| Авторизация | Better Auth: email + пароль, сессии в базе, httpOnly cookie | Готовые роли и бан через admin-плагин; сессию можно отозвать сразу |
| Валидация | Zod (общие схемы для форм и API) | Один источник правил на клиенте и сервере |
| Стили | Tailwind CSS | Быстрая адаптивная вёрстка |
| Картинки игр | `next/image`; файлы в S3-совместимом хранилище (или на диске VPS на старте) | Админ загружает обложки и скриншоты из админки |
| Деплой | Docker Compose на VPS: Next.js (standalone), PostgreSQL, Caddy (HTTPS) | Один сервер, предсказуемая стоимость |
| Почта | SMTP-провайдер (Unisender, Yandex 360, Resend или аналог), шаблоны писем на React Email; домен отправителя с SPF, DKIM и DMARC | Подтверждение email и сброс пароля; без SPF/DKIM письма уходят в спам |

Альтернатива деплою: Vercel + внешний Postgres (Neon или Supabase, у обоих есть бесплатный тариф). Бесплатный тариф Vercel Hobby по условиям только для некоммерческих проектов; для сайта студии — Pro (около $20 в месяц) либо VPS. Условия и лимиты проверить перед выбором. В этом случае счётчики лимитов тоже держать в базе, а не в памяти процесса (раздел 7).

**Структура проекта**

```
app/
  (public)/            главная, игры, доска
  (auth)/              вход, регистрация
  admin/               админка (только role = admin)
  api/                 Route Handlers
lib/server/            сервисы: games, wishes, votes, moderation, rateLimit
lib/db/                схема Drizzle, подключение
lib/validation/        схемы Zod
drizzle/               миграции
```

## 3. Роли и права

Ролей четыре; права проверяются на сервере в каждом запросе, скрытие кнопок в интерфейсе — только удобство.

| Действие | Гость | Пользователь | Забаненный | Админ |
| --- | --- | --- | --- | --- |
| Смотреть сайт, игры и доску | да | да | да | да |
| Регистрация и вход | да | — | вход запрещён, показывается причина и срок бана | да |
| Создать пожелание | нет, кнопка ведёт на вход | да, в пределах лимитов | нет | да, без лимитов |
| Редактировать своё пожелание | — | да, пока у него статус «Новое» и не прошло 15 минут | нет | да (любое) |
| Удалить своё пожелание | — | да, пока статус «Новое» | нет | да (любое) |
| Голосовать и снимать голос | нет, кнопка ведёт на вход | да (в том числе за своё) | нет | да |
| Скрыть / показать / удалить любое пожелание | нет | нет | нет | да |
| Ставить статус и ответ студии | нет | нет | нет | да |
| Банить и разбанивать пользователей | нет | нет | нет | да (кроме других админов) |
| Управлять играми и текстом «О студии» | нет | нет | нет | да |
| Создавать пожелания и голосовать с неподтверждённой почтой | — | нет: можно войти и смотреть, вместо кнопок — баннер «Подтвердите почту» с повторной отправкой письма | нет | почта подтверждается скриптом создания админа |

- Первый админ создаётся скриптом `npm run create-admin -- --email ...`, а не через сайт. Назначить роль админа другому пользователю может только админ.
- Бан сразу завершает все сессии пользователя. Пожелания и голоса забаненного остаются, если админ не отметил «Скрыть все пожелания и аннулировать голоса» (раздел 6).

## 4. Страницы и сценарии

Публичных страниц пять, плюс вход, регистрация, профиль и админка. Все публичные страницы рендерятся на сервере и работают без входа.

| Адрес | Страница | Содержимое | Доступ |
| --- | --- | --- | --- |
| `/` | Главная | Логотип и слоган Odium; коротко о студии (2–3 абзаца); витрина игр карточками; команда (фото, имя, роль) — необязательный блок; контакты и соцсети в подвале | все |
| `/games` | Игры | Сетка карточек: обложка, название, жанр, статус («Вышла» / «В разработке»), платформы, число пожеланий | все |
| `/games/[slug]` | Страница игры | Большая обложка, название, короткое и полное описание, галерея скриншотов, трейлер (YouTube/VK Video по ссылке), дата выхода, платформы со ссылками на сторы, 3 самых популярных пожелания и кнопка **«Оставить пожелание»** | все |
| `/games/[slug]/wishes` | Доска пожеланий | Список пожеланий с сортировкой, фильтрами и голосованием; форма нового пожелания (раздел 5) | просмотр — все |
| `/games/[slug]/wishes/[id]` | Пожелание | Полный текст, автор, дата, статус, ответ студии, кнопка голоса. Отдельный адрес нужен, чтобы идеей можно было поделиться | все |
| `/login`, `/register` | Вход и регистрация | Email + пароль; при регистрации ещё ник. После входа возврат на страницу, с которой пришли (`?next=`) | гости |
| `/profile` | Профиль | Ник, смена пароля, «Мои пожелания» по всем играм, выход, удаление аккаунта | пользователи |
| `/admin/*` | Админка | Раздел 6 | админ |
| /verify-email | Подтверждение почты | Открывается по ссылке из письма: «Почта подтверждена» и переход туда, откуда пришёл пользователь; если ссылка устарела или уже использована — кнопка «Отправить письмо ещё раз» | все |
| /forgot-password, /reset-password | Сброс пароля | Ввод email → письмо со ссылкой; по ссылке форма нового пароля. После смены пароля все сессии завершаются | гости |

**Основной сценарий**

1. Игрок заходит на главную или сразу на страницу игры из стора.
2. Выбирает игру, читает описание и нажимает «Оставить пожелание» — открывается доска.
3. Смотрит чужие идеи и нажимает «Голосовать» или «Новое пожелание».
4. Если не вошёл — окно «Войдите, чтобы голосовать и предлагать идеи» с кнопками входа и регистрации; после них игрок возвращается на ту же доску.

## 5. Доска пожеланий

У каждой игры своя доска. Пожелание бывает двух типов: **«Добавить»** и **«Убрать»**. Один пользователь даёт одному пожеланию не больше одного голоса и может его снять.

### Карточка пожелания

- Счётчик голосов с кнопкой-переключателем (залита, если пользователь уже голосовал).
- Метка типа («Добавить» — зелёная, «Убрать» — красная) и метка статуса.
- Заголовок, первые 2 строки описания, ник автора, дата («3 дня назад»).
- Если есть ответ студии — значок «Ответ Odium».

### Создание

| Поле | Правило |
| --- | --- |
| Тип | «Добавить» или «Убрать», обязательно |
| Заголовок | 5–100 символов, обязательно |
| Описание | 0–2000 символов, простой текст (переносы строк сохраняются, HTML и Markdown не интерпретируются, ссылки не кликабельны) |

- Пока пользователь пишет заголовок, под полем показываются до 3 похожих пожеланий этой игры (поиск по словам через `pg_trgm`) с подсказкой «Может, проголосуете за уже существующее?». Это снижает число дублей.
- Автор автоматически голосует за своё пожелание (счётчик стартует с 1); этот голос можно снять.
- Новое пожелание сразу видно всем (предмодерации нет) со статусом «Новое».

### Голосование

- Кнопка работает как переключатель: первое нажатие ставит голос, повторное снимает.
- Интерфейс меняет счётчик сразу (optimistic update) и откатывает его с сообщением, если сервер отказал.
- Сервер делает вставку или удаление голоса и пересчёт `votes_count` в одной транзакции. Двойной голос невозможен благодаря первичному ключу `(wish_id, user_id)`; запросы идемпотентны (`PUT` ставит, `DELETE` снимает).
- За скрытые пожелания и пожелания со статусом «Сделано» или «Отклонено» голосовать нельзя; уже поставленные голоса сохраняются.

### Сортировка и фильтры

Выбор сохраняется в адресе (`?sort=top&type=add&status=planned`), чтобы ссылкой можно было поделиться.

| Сортировка | Как считается |
| --- | --- |
| Популярные (по умолчанию) | `votes_count` по убыванию, при равенстве — новее выше |
| Новые | `created_at` по убыванию |
| В тренде | число голосов за последние 7 дней |
| Старые | `created_at` по возрастанию |

Фильтры: тип (все / добавить / убрать), статус (по умолчанию скрыты «Сделано» и «Отклонено»), «Мои пожелания», «Я голосовал», поиск по тексту. Подгрузка по 20 штук кнопкой «Показать ещё» (курсорная пагинация).

### Статусы

| Статус | Значение |
| --- | --- |
| Новое | Ставится при создании |
| На рассмотрении | Студия прочитала и обсуждает |
| Запланировано | Взято в планы |
| В работе | Делается |
| Сделано | Вошло в игру (можно указать версию) |
| Отклонено | Не будет сделано; ответ студии с причиной обязателен |

Статус независим от скрытия: скрытое пожелание сохраняет свой статус и видно только админу и автору (с пометкой «Скрыто модератором»).

## 6. Модерация и админка

Админка находится по адресу `/admin`; страницы и API проверяют `role = admin` на сервере, остальным отдаётся 404. Каждое действие админа пишется в журнал.

| Раздел | Что умеет |
| --- | --- |
| Пожелания | Таблица по всем играм с фильтрами (игра, статус, тип, скрытые, автор) и сортировкой. Действия: сменить статус, написать ответ студии, скрыть / показать, удалить, отредактировать, объединить дубль с оригиналом. Массовые действия для выделенных строк |
| Пользователи | Поиск по нику и email; карточка с датой регистрации, числом пожеланий и голосов, историей банов. Действия: забанить, разбанить, назначить или снять роль админа |
| Игры | Создание и редактирование игр: название, slug, описания (Markdown), обложка, скриншоты, трейлер, ссылки на сторы, статус, порядок в каталоге. Доску игры можно закрыть для новых пожеланий (чтение остаётся) |
| О студии | Текст для главной, список команды, контакты и ссылки на соцсети |
| Журнал | Все действия админов: кто, что, над чем, когда, старое и новое значение |

### Действия с пожеланиями

- **Скрыть**: пожелание пропадает с доски и из поиска, но остаётся в базе вместе с голосами. Админ выбирает причину (спам, оскорбление, не по теме, дубль, другое); автор видит причину у себя в профиле. Обратимо.
- **Удалить**: мягкое удаление (`deleted_at`), через 30 дней фоновая задача удаляет насовсем вместе с голосами. Подтверждение диалогом.
- **Статус и ответ**: ответ студии — до 1000 символов, показывается под пожеланием с пометкой «Ответ Odium». Для «Отклонено» ответ обязателен.
- **Объединить дубль**: голоса дубля переносятся на оригинал (без повторных голосов одного человека), дубль скрывается с причиной «дубль» и ссылкой на оригинал.

### Бан

- Срок: 1 день, 7 дней, 30 дней или навсегда. Причина обязательна и показывается пользователю при попытке входа.
- Галочка «Скрыть все пожелания и аннулировать голоса» — для спамеров и накрутки. Счётчики затронутых пожеланий пересчитываются в той же транзакции.
- Временный бан снимается автоматически по истечении срока (проверка `ban_expires_at` при каждом запросе, без cron).

## 7. Антиспам и безопасность

Защита от спама строится на лимитах частоты и проверках содержимого. Капчи нет. От ботов защищают обязательное подтверждение email (без него нельзя создавать пожелания и голосовать) и ограничения для свежих аккаунтов.

### Лимиты

| Действие | Ключ | Лимит |
| --- | --- | --- |
| Регистрация | IP | 3 в час |
| Вход (неудачные попытки) | IP + email | 10 за 15 минут, далее блокировка на 15 минут |
| Создание пожелания | пользователь | 5 в час и 20 в сутки |
| Создание пожелания, аккаунт моложе 24 часов | пользователь | 2 в сутки |
| Редактирование своего пожелания | пользователь | 10 в час |
| Голос и снятие голоса | пользователь | 60 в минуту |
| Любой запрос к API | IP | 300 в минуту |
| Повторная отправка письма подтверждения | пользователь | 1 в минуту и 5 в сутки |
| Запрос сброса пароля | email и IP отдельно | 3 в час |

- Реализация: скользящее окно или фиксированные окна в таблице Postgres `rate_limits` (ключ, окно, счётчик), атомарно через `INSERT … ON CONFLICT DO UPDATE`. Работает одинаково на VPS и на serverless.
- Все лимиты — в одном конфиге `lib/server/limits.ts`, чтобы менять без поиска по коду. Админы от лимитов на создание освобождены.
- При превышении: ответ `429` с заголовком `Retry-After`; в интерфейсе текст «Слишком часто, попробуйте через N минут».
- IP берётся из `X-Forwarded-For` только от доверенного прокси (Caddy).

### Проверки содержимого

- Запрет полных дублей: тот же автор, та же игра и тот же заголовок после нормализации (регистр, пробелы, ё→е) — отказ с сообщением.
- Стоп-слова: список в админке; пожелание со стоп-словом создаётся сразу скрытым и попадает в фильтр «На проверку» админки.
- В тексте не больше 2 ссылок; заголовок не может быть целиком в верхнем регистре, длиннее 10 символов.
- Ник: 3–24 символа, буквы, цифры, `_` и `-`, уникален без учёта регистра; зарезервированы `admin`, `odium`, `moderator` и похожие.

### Безопасность

- Пароли — минимум 8 символов, хеш через scrypt/argon2 (средства Better Auth). Сообщение об ошибке входа не говорит, что именно неверно.
- Сессия — httpOnly, Secure, SameSite=Lax cookie; срок 30 дней с продлением; смена пароля и бан завершают все сессии.
- Изменяющие запросы проверяют заголовок `Origin` (защита от CSRF).
- Пользовательский текст выводится только как текст (без `dangerouslySetInnerHTML`); Markdown есть только в описаниях игр от админа.
- Заголовки: CSP, `X-Content-Type-Options`, `Referrer-Policy`, `frame-ancestors 'none'`.
- Удаление аккаунта по запросу пользователя: email и пароль стираются, голоса удаляются, пожелания остаются от имени «Удалённый пользователь». Политика конфиденциальности обязательна, так как собираются email.

**Подтверждение почты и сброс пароля**

- Письмо подтверждения уходит сразу после регистрации; ссылка одноразовая и действует 24 часа. После подтверждения пользователь автоматически входит и возвращается на страницу, с которой регистрировался.
- Ссылка сброса пароля одноразовая и действует 1 час. На запрос сброса сайт всегда отвечает одинаково («Если такой адрес зарегистрирован, мы отправили письмо»), чтобы по ответу нельзя было проверить, есть ли email в базе.
- Смена email в профиле: новый адрес вступает в силу только после подтверждения письмом на него; на старый приходит уведомление.
- Неподтверждённые аккаунты старше 7 дней удаляются фоновой задачей, ник освобождается.
- Одноразовые и временные адреса (mailinator и т. п.) отклоняются по списку доменов.

## 8. Модель данных

Таблицы `user`, `session`, `account` создаёт Better Auth (admin-плагин добавляет в `user` поля `role`, `banned`, `ban_reason`, `ban_expires`); ниже — таблицы приложения. Все id — UUID, время — `timestamptz`.

| Таблица | Поля | Ограничения и индексы |
| --- | --- | --- |
| `user` (дополнение) | `nickname`, `created_at` | `nickname` уникален по `lower(nickname)` |
| `games` | `id`, `slug`, `title`, `tagline`, `description_md`, `cover_url`, `screenshots` (jsonb), `trailer_url`, `genre`, `platforms` (jsonb: платформа + ссылка), `status` (released / in\_development), `release_date`, `sort_order`, `wishes_open` (bool), `published` (bool), `created_at`, `updated_at` | `slug` уникален |
| `wishes` | `id`, `game_id`, `author_id`, `type` (add / remove), `title`, `body`, `status` (new / review / planned / in\_progress / done / declined), `studio_reply`, `done_version`, `votes_count` (int), `hidden` (bool), `hidden_reason`, `merged_into_id`, `created_at`, `updated_at`, `deleted_at` | индексы `(game_id, hidden, votes_count desc, created_at desc)` и `(game_id, hidden, created_at desc)`; GIN-индекс `pg_trgm` по `title` |
| `votes` | `wish_id`, `user_id`, `created_at` | `PRIMARY KEY (wish_id, user_id)`; индекс `(user_id)`; индекс `(wish_id, created_at)` для «В тренде» |
| `studio_info` | одна строка: `about_md`, `team` (jsonb), `socials` (jsonb), `contacts`, `updated_at` | — |
| `stop_words` | `id`, `word` | уникально |
| `rate_limits` | `key`, `window_start`, `count` | `PRIMARY KEY (key, window_start)`; старые окна чистятся раз в сутки |
| `admin_log` | `id`, `admin_id`, `action`, `target_type`, `target_id`, `before` (jsonb), `after` (jsonb), `reason`, `created_at` | индекс `(created_at desc)` |

**Правила целостности**

- `votes_count` меняется только в той же транзакции, что и `votes` (или триггером). Раз в сутки фоновая задача сверяет счётчики с `count(*)`.
- Удаление игры запрещено, пока у неё есть пожелания; вместо этого снимается с публикации (`published = false`).
- `votes` удаляется каскадом при окончательном удалении пожелания или пользователя.

**Подтверждение почты** хранится в поле `email_verified` таблицы `user`; одноразовые токены подтверждения и сброса пароля — в таблице `verification` (обе создаёт Better Auth). Список запрещённых одноразовых доменов — таблица `blocked_email_domains` (`domain`, уникально), редактируется в админке рядом со стоп-словами.

## 9. API

Все эндпоинты — Route Handlers под `/api`, JSON на входе и выходе, входящие данные проверяются Zod. Авторизация — cookie сессии. Авторизационные маршруты Better Auth живут под `/api/auth/*`.

| Метод и путь | Что делает | Доступ |
| --- | --- | --- |
| `POST /api/auth/sign-up`, `/sign-in`, `/sign-out` | Регистрация, вход, выход (Better Auth) | все |
| `GET /api/me` | Текущий пользователь или `null` | все |
| `PATCH /api/me` | Смена ника или пароля | пользователь |
| `DELETE /api/me` | Удаление аккаунта (с паролем) | пользователь |
| `GET /api/games` | Опубликованные игры | все |
| `GET /api/games/:slug` | Игра подробно | все |
| `GET /api/games/:slug/wishes?sort=&type=&status=&q=&mine=&voted=&cursor=` | Список пожеланий (20 шт.) + `nextCursor`; у каждого поле `votedByMe` | все |
| `GET /api/games/:slug/wishes/similar?q=` | До 3 похожих по заголовку | все |
| `POST /api/games/:slug/wishes` | Создать пожелание | пользователь, лимит |
| `GET /api/wishes/:id` | Одно пожелание | все (скрытое — автор и админ) |
| `PATCH /api/wishes/:id` | Правка своего пожелания | автор (раздел 3) |
| `DELETE /api/wishes/:id` | Удаление своего пожелания | автор (статус «Новое») |
| `PUT /api/wishes/:id/vote` | Поставить голос → `{ votesCount, votedByMe: true }` | пользователь, лимит |
| `DELETE /api/wishes/:id/vote` | Снять голос → `{ votesCount, votedByMe: false }` | пользователь, лимит |
| `GET /api/me/wishes` | Мои пожелания по всем играм (включая скрытые с причиной) | пользователь |
| `GET /api/admin/wishes` | Список для модерации с фильтрами | админ |
| `PATCH /api/admin/wishes/:id` | Статус, ответ, `hidden` + причина, правка текста | админ |
| `POST /api/admin/wishes/:id/merge` | Объединить с `{ targetId }` | админ |
| `DELETE /api/admin/wishes/:id` | Удалить | админ |
| `POST /api/admin/wishes/bulk` | Массово: скрыть, показать, удалить, статус | админ |
| `GET /api/admin/users`, `GET /api/admin/users/:id` | Поиск и карточка пользователя | админ |
| `POST /api/admin/users/:id/ban`, `DELETE …/ban` | Бан `{ reason, duration, wipe }` и разбан | админ |
| `PATCH /api/admin/users/:id/role` | Назначить или снять админа | админ |
| `POST/PATCH/DELETE /api/admin/games[/:id]` | Управление играми | админ |
| `POST /api/admin/uploads` | Загрузка картинки (JPG/PNG/WebP до 5 МБ) → URL | админ |
| `PUT /api/admin/studio`, `PUT /api/admin/stop-words` | Текст «О студии», стоп-слова | админ |
| `GET /api/admin/log` | Журнал действий | админ |
| GET /api/auth/verify-email?token= | Подтвердить почту по ссылке из письма (Better Auth) | все |
| POST /api/auth/send-verification-email | Отправить письмо подтверждения ещё раз (Better Auth) | пользователь, лимит |
| POST /api/auth/request-password-reset, POST /api/auth/reset-password | Запросить письмо сброса и задать новый пароль по токену (Better Auth; точные пути сверить с версией библиотеки) | все, лимит |

**Формат ошибок**: `{ "error": { "code": "RATE_LIMITED", "message": "…", "fields"?: {…} } }` с кодами HTTP 400 (валидация), 401 (не вошёл), 403 (нет прав, бан или неподтверждённая почта — код EMAIL\_NOT\_VERIFIED), 404, 409 (дубль, доска закрыта), 429 (лимит).

После изменений сервер сбрасывает кэш затронутых страниц через `revalidateTag` (теги `game:<slug>`, `wishes:<gameId>`).

## 10. Нефункциональные требования и этапы

### Требования

- **Адаптивность**: mobile-first, корректно от 360 px до 1920 px ширины.
- **Скорость**: Lighthouse Performance ≥ 90 на мобильном для главной и страницы игры; LCP < 2,5 с; ответ API < 200 мс на список из 10 000 пожеланий.
- **SEO**: уникальные title и description для каждой игры, Open Graph картинки для игр и пожеланий, `sitemap.xml` и `robots.txt` (админка и профиль закрыты от индексации), разметка schema.org `VideoGame`.
- **Доступность**: управление с клавиатуры, видимый фокус, контраст текста не ниже WCAG AA, `alt` у картинок, кнопка голоса с `aria-pressed`.
- **Дизайн**: фирменный стиль Odium (логотип, цвета, шрифты передаёт студия); тёмная тема по умолчанию — по решению студии.
- **Надёжность**: ежедневный `pg_dump` с хранением 14 дней вне сервера; логи ошибок (Sentry или аналог); эндпоинт `/api/health`.
- **Качество кода**: ESLint + Prettier, TypeScript strict; юнит-тесты сервисного слоя (голоса, лимиты, права) на Vitest; e2e основного сценария на Playwright; CI прогоняет линтер, типы и тесты.
- **Конфигурация**: все секреты в переменных окружения (`DATABASE_URL`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, доступы к хранилищу, SMTP\_HOST, SMTP\_PORT, SMTP\_USER, SMTP\_PASSWORD, MAIL\_FROM), пример в `.env.example`.
